# 可见 GUI 工作流（持续扩展）

当前开发顺序：先完成可见、最大化的 GUI 操作与验收，再适配 `-nographics` 与 `runc=` 两种无 GUI 路径。本页新增验收限 Windows LS-PrePost 2026R1(v4.13.4)。旧版本和无 GUI 模式不能自动继承这些结论。

## 本轮正式工具

原生曲线图增量：`export_gui_curve_plot` 已接入明确 CSV 列→独立 XYPlot→图题/轴/单位→PNG及数值读回，保留滞回点序和原工程 CSV。合成应力应变改面积录制回放、旧图数据保持、代表性原生位移提取到图片均通过。XYPlot 内部单精度明确标注；多曲线/完整曲线窗口尚未覆盖。

每次编辑先保存基线，执行后核对坐标、真实 ID、连接关系和部件归属，保存新 k 文件。失败时保留基线与失败证据，标记会话不确定，不把“命令记录存在”当作模型修改成功。

现在区分 `transaction_kind=edit/selection/inspection`。只有 edit 自动保存前后 k 检查点；选择/原生检查保留原有检查点和 dirty 状态，不再为每个查询保存两份整模 k。它们仍读回并核对网格，报告/选择状态与显示可能变化。`checkpoint_created=false` 表示本次未创建模型检查点，不代表没有证据文件。验证异常时仍保守标记不确定。

4.13.4 已验 ID 选择、Buffer 保存/清空/加载均不新增 keyword 导出；原生检查同样无自动 k 导出，实际编辑仍保留检查点。完整质量门槛/策略录制/参数回放再次通过。后续增量已将显式 ID 选择/集合运算/Buffer 和节点平移/旋转/绝对坐标修改迁移到完整流式摘要校验；其余整模快照路径仍有20000限制。具体原生规模证据见 [MODEL_SCALE.md](MODEL_SCALE.md)。

绝对坐标操作使用 `nodes=[{"id":2,"coordinates":[3,null,null]}]` 这样的结构，表示 X=3，Y/Z 保持。`tolerance` 是当前长度单位下的正绝对容差；未请求节点要求原生读回完全一致。工具报告受影响单元的数量与样本，连接关系保持；材料轴、载荷方向与质量合格不能从坐标核对推断。

`tools/run_gui_coordinate_acceptance.py` 已在最大化 4.13.4 中跑通：X 对齐→原生壳质量→保存重开；录制后修改目标坐标回放；故意拉长到超限，后续保存被门槛阻止；显式恢复修改前检查点；隐藏部件中的完整 XYZ、多组不同位移及显示恢复。使用自建合成模型，原文件哈希不变。投影、等距分布和完整节点编辑菜单仍待开发。

## 选择命令修正

从界面录制发现，`genselect node add node 2/2` 中的模型限定信息会随打开/重开模型改变。固定 `/0` 会在当前模型不再是首个模型时选不到指定节点。新工具使用未限定模型后缀的用户 ID，作用于当前模型；实际读回选择集和变化坐标进行验证。

这纠正了 v0.3 GUI 原位变换失败的原因。协议 3 的新会话中，原有 `gui_session_action` 平移/旋转请求也路由至新可见 GUI 实现；旧协议会话仍保留原有路径，应保存后新建会话使用新实现。跨多个模型的显式选择与一般录制转换仍需继续开发。

## 会话配置与可见性

2026-10-05 加载校验修复：打开或重置模型的原生响应必须匹配本次暂存输入的文件/独立目录，节点与状态计数必须有效，并检查本次请求新增的原生日志错误。即时完成与超时后的恢复采用相同校验；失败不更新可信来源、模型类型或模型代际，保留原始响应并将会话标为 `uncertain`。

零实体录制增补：录制开始时即便节点/单元为0，也保存原生keyword基线及 `initial_expected_empty`。回放要求实际恢复0节点/0单元，材料等基线卡片保留；普通打开仍默认拒绝意外零节点。显式打开/检查点恢复可传 `expected_empty=True`，仍检查活动来源和原生日志。4.13.4材料-only基线→建节点→加入额外节点→换ID回放通过，最终只有201/205且材料卡保持；原来的空起点工程曲线录制也重新通过。见[恢复合同](SESSION_RECOVERY.md#zero-entity-keyword-baselines)。

4.13.4 可见 GUI 回归：官方复材/SPH 示例的新会话关键字读取（2957节点、3005单元、1状态）及关键字→结果（3状态）成功；结果→关键字产生原生 `Invalid entity ID! ** Prog Error` 时正确返回失败，旧来源与代际保持，源文件哈希不变。548项测试通过，包括延迟恢复、旧日志隔离、日志截断与相邻文件误识别反例。

**这仅验证当前活动来源，不证明模型列表只有一个条目。** 原生 Model Selection 实测显示初始化模型与后续打开模型可同时存在。新增模型清单读取见下节；完整替换、关联关键字与多模型切换仍待独立实现和验收，B0-03保持partial。不要用 `new` 代替卸载：该构建会弹出重启会话提示。

### 原生模型清单与编号边界（2026-10-05）

`inspect_gui_session(session_id, include_models=True)` 在会话锁内打开该进程的 Model Selection 面板，读取原生两列列表。默认 `False` 仍只读取会话元数据。返回 `row_index`（当前1起行号）、`display_label`、可解析时的 `display_number`、标题与原生来源路径。`active_row_index_candidate` 仅由唯一来源路径/目录匹配推断，重复来源或无法匹配时返回 null；不是任意多模型场景的确定身份。

4.13.4 最大化可见 GUI 合成验收：清单数量依次为1→3→2→1；移除初始模型后，原生标签仍为2/3，但行号为1/2。同一个第二行模型，GUI录制得到 `model select 2` 和 `model remove 3`；按这两个不同编号执行后，分别核对活动来源和剩余模型成功。移除非活动的初始模型也会改变活动模型，因此修改列表后必须重新读回。此证据不定义其他版本、重复显示编号、`genselect` 模型后缀或一般删除接口。

读取前后核对活动模型的节点/单元计数、Part ID、状态与来源；不一致则标记 uncertain。面板会保留打开，不能据此宣称完整视口、选区或场景保持。实现限 Windows x64、原生非 owner-data 的两列 ListView，最多256行、每单元格2048字符缓冲；这是模型清单读取预算，不是节点/单元数量限制。使用受管进程临时数据缓冲，不注入可执行代码；若同步消息超时，不重试并保留该小缓冲至进程退出，避免延迟消息访问已释放内存。强制卡死情况下的这条清理路径尚未实机注入测试。

可复现实机驱动：`tools/run_model_inventory_acceptance.py`；数据解析/歧义测试：`tests/test_model_list.py`。它验证清单和合成命令编号关系；显式受管激活见下一节，remove/replace仍待实现。原始合成输入逐字节保持；失败探索记录留在本地。

### 显式切换已载入模型

`activate_gui_model(session_id, source_path)` 接受本会话成功打开的 `staged_model`，或原生模型列表中与其对应的已验证检查点路径。它按刷新后的行号选择内存中现有模型，不重开、不卸载。切换前保存当前 keyword 内存，切换后核对目标来源、模型类型和列表保持，再保存目标 keyword，更新活动来源/检查点并使受管选区、显隐和场缓存失效。相同来源已活动时不重复提交选择命令。已有会话中未登记的模型需要先用正式打开流程建立归属，不能凭标题或裸编号接管。

实机发现：原生 `model_directory` 及 Model Selection 路径在保存、切换或重新加载列表后可变为该模型最近保存位置。因此受管记录同时保留最初暂存来源、当前检查点和上次已核实来源；匹配检查点路径时，须验证文件侧车的会话归属及文件身份。不能把任意任务目录或相邻文件当作同一模型。模型清单里的纯路径活动候选仍可能为null，不等同于有错误。

4.13.4 最大化 GUI 验收：两个独立合成模型分别新增301/401，反复切换后只在各自模型读到对应节点及坐标；保存过的 Buffer 在切换后拒绝旧缓存；相同来源不重复选择；非受管来源和录制期间的切换前置拒绝。加入官方 general d3plot（1065节点、548单元、22状态），结果→已有关键字A→结果→已有关键字B通过，A/B编辑保持，结果模型不错误继承keyword检查点，源文件及结果文件族SHA-256保持。

驱动：`tools/run_resident_activation_acceptance.py`（`--d3plot` 显式指定本地结果）。本增量不解决 `open keyword` 在活动结果上重新加载的全部关联问题；也不认证任意手工切换、多层Include保真、视口/选区完整恢复、全部resident模型崩溃恢复、旧版本或无GUI。当前录制是单基线语义，活动录制时拒绝此操作，不能静默遗漏切换步骤。完整卸载/替换/关联仍保留为P0后续项，B0-03保持partial。

通过厂商支持的 `LSTC_FILE` 路径，为每个新 GUI 会话建立私有配置副本。保留现有 Python home、隐私选择和其他非路径偏好，只重定向任务日志/工作目录；不修改用户原配置。可用 `LSPP_CONFIG_SOURCE` 指定要复制的配置文件。

桌面锁定时拒绝可见 GUI 输入。首次安装缺少既有配置时，软件可能要求用户完成初始设置；工具不会替用户改变隐私选择。

部分构建的标题栏仍可能显示错误的组合文件路径；实际产物以任务目录中的新文件及指纹为准。新建会话不能使用 `new` 启动命令，因为部分 GUI 状态下会被解释为重启并弹出确认框。

## 已跑通的合成流程

5 节点/1 壳 → 合并为 4 节点 → 反转法向 → 仅平移节点 2、3 → 整体旋转 → 增加节点 6、7 → 向原部件增加壳 20 → 6 节点/2 壳 → 几何质量检查与 PNG。所有编辑发生在同一可见 GUI 中，节点和部件均读回核对。

节点、壳单元和部件的正式 Renumber 工具均已在同一可见 4.13.4 GUI 实测：6 节点改为 1000–1005、2 壳改为 2000–2001、部件改为 3000，坐标、连接、部件归属和节点集合同步引用通过核对。数字是合成验收案例。工具读取原生编号映射，不硬编码各版本不同的 keyword kind 编号。仅认证该构建及上述范围；偏移、部分实体、所有关键字引用仍需拓展。

修复了原生导出 `SET_NODE_LIST` 补零被引用检查误认为缺失节点的问题。`0` 占位不计入集合，真正缺失的非零节点仍报错。

选择缓存已跑通“开始录制 → 保存节点选区 → 清空 → 加载 → 停止录制 → 参数化节点 ID → 原生重开基线 → 在同一 GUI 回放 → 核对新选区”的完整流程。录制包含 3 个受管操作；参数从合成节点 1000/1001 改为 1002/1003 后回放正确。原生鼠标操作的通用语义转换仍是独立缺口。

原始 cfile 转换现支持已声明目标的 ID/全选/反选、同文件保存后清空再加载的原生缓冲区、节点平移、局部壳法向反转和原生壳质量检查。实测 13 步 cfile 转换后在同一可见 GUI 回放成功；全选/缓冲区加载通过 `$result` 绑定真实读回 ID，不猜测节点编号。

带模型后缀的 ID（例如 `12/2`）必须显式传 `recorded_model_index=2`，表示将录制中的这一模型映射到当前模型；不匹配/跨模型录制阻止回放。旧版默默剥离 `/0` 的逻辑已移除。改变选择目标前必须明确清空；未知缓冲区、未清空就加载、未知命令和不透明脚本继续保留审查阻断。复杂鼠标拾取、原生宏菜单和全部命令语法尚未覆盖。

## 原生 Model Checking 的新验收

路径是 `Application → Model Checking → General Checking`。右侧 Model 的 `RefCheck` 是另一个引用/连接关系面板，不能代替它。新的壳质量工具逐项执行并读取原生统计：最短/最长边、长宽比、翘曲、四边壳最小/最大角、三角壳最小/最大角、Taper、Skew、Jacobian、特征长度、面积。没有对应拓扑的指标返回 `not_applicable`。

矩形壳的原生长宽比为 2，上限 10 时通过，上限 1.5 时 2 个壳违规（100%）。另外用原生导入新增独立三角壳，最小/最大角 45°/90°，最小角阈值 60° 时正确报出 1 个违规壳。所有检查后核对网格未改变。数值为合成案例；未公开用户仿真数据。

`status=succeeded` 表示检查成功执行，模型是否满足指定阈值看 `verification.passed_checks`；全部指标不适用时为 `null`。这些阈值是用户输入，不代表求解质量标准。原生 Jacobian 的定义/显示值与几何数学后端不同，两个后端必须分别标注。百分比保留原生口径：混合模型的三角壳角度违规 1 个时，原生显示占全部 3 壳的 33.3%，并非占三角壳的比例。工具同时返回对应拓扑数量与全部壳数量。

Keyword Check 现已独立接入：报告必须包含原生头尾标记和完整四项汇总，保留分组及原始明细，并核对检查前后网格。正常合成模型有 1 个未引用集合；故意缺材料/截面的反例报 4 warning、1 error、2 undefine，工具正确保留这些发现，不清理/删除它们。该工具和 PyDYNA 的限定引用检查是不同后端。原生 Keyword Check 也不能证明求解模型物理正确。

上段是早期壳检查增量。后续已补Hex8六项质量及可选失败单元ID定位（见下节）；全部壳/其他实体/梁的失败ID闭环、Contact Check、自动修复和旧版本仍待补。不能把逐准则违规数相加冒充独立失败单元总数。

## 原生实体质量门槛

`check_gui_solid_quality` 使用 `checks=[{"metric":"aspect_ratio","comparison":"gt","threshold":1.5}]`。gt/lt 表示由原生检查器判断“大于/小于阈值”的失败实体；不自动改为包含边界的比较。支持 `minimum_angle`、`maximum_angle`、`distortion_index`、`volume`、`characteristic_length`、`aspect_ratio`。检查全体部件，检查后恢复部件活动标志；检查显示及原生捕获状态可以变化。

本机检查通过时不输出零失败日志，因此工具要求相关原生命令完成、命令日志匹配、原生 Save Failed 按钮明确禁用，才报告 0。失败时同时核对原生数量、百分比与捕获按钮状态。缺失/矛盾证据会失败，不能把空日志直接当通过。报告是逐准则计数，同一单元可能触发多项，不能将它们相加当作失败实体并集。

`tools/run_gui_solid_quality_acceptance.py` 以两个合成 Hex8 验证 6 项各自通过/失败、部分超限 1/2、隐藏部件仍被检查且显隐恢复、检查不导出 k、超限阻止节点编辑，以及录制后修改阈值回放仍阻止编辑。原文件指纹保持。当前限非空 Hex8 实体集合与 20000 实体快照；四面体/厚壳/梁、时间步、接触和自动修复继续开发。

### 失败集合捕获与定位

`capture_failed_ids=true` 使用本机构建实际记录的 `elemcheck savetogen`，通过原生 Buffer1 读出失败用户 ID。每个准则的数量、唯一性和当前实体注册表都必须一致；不同准则的完整 ID 单独存 JSON，返回有限样本以及独立去重的 `failed_element_ids` / `unique_failed_element_count` / `failed_part_ids`。未请求捕获时不返回 ID 集合字段；工作流绑定缺失字段会失败，不把 null 误传成选择工具的“全选”默认值。

这一可选模式会覆盖原生 Buffer1，并在完成时清空通用选区；其他缓冲槽保留。受管 Buffer1 身份在发命令前作废，已有受管元数据保存为恢复参考；这不是未知手工缓存内容的快照。随后可把 `failed_element_ids` 绑定给 `select_gui_entities`。默认统计模式不改变受管缓存身份。

仅定位问题、不要求质量合格时，[定位配方](../examples/workflows/visible_gui_locate_failed_solids.json) 明确使用 `quality_policy="report_only"`，然后选择失败并集；它没有批准继续编辑坏网格。原生验证使用不连续单元 ID 101/507，分别捕获不同体积条件、验证通过后的空集合、其他缓冲槽保留，并验证录制后改阈值会选择新的失败集合。入口为 `tools/run_gui_failed_ids_acceptance.py`。

模型重开、重置和检查点替换会作废旧受管选区缓存身份，即使新模型坐标/ID 恰好相同。旧配方若依赖录制开始前的缓存，应把保存选区步骤纳入模板。打开 d3plot 时也会清除上一 keyword 的默认检查点引用；原文件、历史检查点和日志仍保留，可通过明确路径恢复。
