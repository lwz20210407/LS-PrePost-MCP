# 显式模型替换与失败保护

归属 runtime / T03 / A01-A02，支持 WF-MESH、WF-POST、WF-AUTO 的模型身份基础；当前替换工具本身尚未进入多模型录制。验收范围为 Windows LS-PrePost 4.13.4 可见最大化 GUI。

新增实测限制：官方角运动双壳原例在原位替换后的导出中出现原生退出，详见[NATIVE-REPLACE-001](NATIVE_KNOWN_ISSUES.md)。本页限定成功矩阵不构成任意模型或长会话稳定性认证。

## 工具与边界

`replace_gui_model(session_id, path, file_type="keyword", expected_empty=False)` 替换当前受管模型，保持同一进程和其他已载入模型。首次载入仍用 `open_in_gui_session`；需要明确替换时使用本工具，不把普通打开、关键字关联和替换混为一谈。参数 `expected_empty=True` 只适用于明确预期零节点/零单元的keyword文件，仍核对来源、状态、日志和模型列表。

流程：校验当前来源及列表 → 暂存新输入 → 保存旧keyword内存 → 从结果模式离开时创建并保存临时空keyword模型 → 验证新文件载入和已有模型保持 → 卸载旧模型 → 清理本次临时模型 → 核对最终列表与活动来源。原模型文件不覆盖或删除；旧keyword检查点在 `old_checkpoint` 返回，恢复新检查点需显式操作。

每次卸载后，keyword保留模型必须完成一次原生导出并核对来源、计数及文件绑定，随后重新核对模型列表。`survivor_export` 标明此检查结果；结果数据库不转存keyword，返回 `not_applicable`。不完整或崩溃的保存不能覆盖移除前检查点。这个检查能提前发现已复现的“移除后下一次保存退出”，不能保证任意后续操作稳定。

`cemptymodel` 的线索来自已登记的本地SCL/几何案例，并在本机验证：它从结果模式创建空模型，但在已有keyword模式下不会清空该模型，因此只在离开结果模式时使用。临时模型必须有本次任务的绝对文件身份，不能按标题或猜测编号清理。

在测试构建中，直接从一个结果打开另一个结果、以及在另一结果活动时移除旧结果，分别出现过原生退出或失去响应。替换保留一个已核实的keyword中间模型直到旧结果卸载完成。`unload_gui_model` 对结果→结果的目标组合也先使用已验证的resident keyword作临时活动模型，再激活用户指定的结果；找不到此中间模型时前置拒绝。不会偷偷换进程或转无GUI。

事务内部读完 Model Selection 后关闭该面板，再载入/切换/移除模型；独立的 `inspect_gui_session(include_models=True)` 仍按原合同保留面板。保存会刷新列表路径，比较时使用已核实来源及文件别名，而不是要求路径字符串始终不变。

## 失败结果

- 未准备好、请求未结束或正在录制时前置拒绝。
- 新文件载入不符合合同，旧模型不会进入卸载阶段；保留原生请求、响应、日志及检查点，会话标记 uncertain。
- `old_model_unloaded` 为 `false` 表示尚未提交旧模型移除，`true` 表示已通过移除核对，`null` 表示移除结果不确定。超时不能当作“未移除”，也不能重复发送。
- 成功载入后，卸载或临时清理仍可能失败；这不是原子回滚。读取 `phases` 与恢复提示，检查实际模型状态后处理。
- 即使整体 `status=failed`，若模型列表已证实旧模型移除，`old_model_unloaded` 仍为 `true`；后续导出失败不能把已知移除改成未移除或未知。失败详情沿 `phases` 指向原生请求；只能显式恢复，不自动重试。
- 活动录制暂不接受本工具；不能静默丢掉模型切换步骤。任意手工状态、关联keyword/result、多层Include保真、完整视口/选区恢复和全模型崩溃恢复仍未认证。

## 可复现原生验收

`tools/run_model_replacement_acceptance.py` 使用三个合成keyword和显式指定的公开结果文件，覆盖：

1. keyword→result、result→keyword检查点、keyword→keyword、result→另一result；使用官方general（1065节点/548单元/22状态）和beam（1940节点/2056单元/12状态）结果。
2. 每次成功保留“初始化模型、独立keeper、当前模型”三条记录，无临时模型累积。
3. 被替换keyword的301节点通过检查点原生重开恢复；未被替换keeper的601节点始终保持。
4. 显式空keyword成功；未声明空模型时拒绝，旧模型尚未卸载。关闭测试进程后在新的受管GUI中重开失败前检查点，601节点仍在。
5. 原始keyword与结果文件族SHA-256不变。

`tools/run_stale_model_regression.py` 针对曾经触发误报的公开鸟撞案例：新会话input.k为2957节点/3005单元/1状态；普通结果→keyword打开再次出现原生错误时正确失败，来源/模型代际/类型不推进。另一个受管会话使用显式替换，则正确进入1状态keyword，旧结果和临时模型移除，最终仅初始化模型与新模型。这仅认证来源和模型库存，不认证SPH/复材场数组。

同时重新运行 `tools/run_gui_gate_acceptance.py`：原生壳质量失败、keyword检查失败、录制回放门槛失败都阻断后续修改；明确通过的检查与显式策略按合同继续。结合上述旧模型误报回归，恢复冻结台账的 **B0-03**；其余未完成门槛与全部软件覆盖率不因此改变。
