# I01：自有关键字输入副本

原生读取入口从共享 Include 预检得到整棵树，按实际解析目标为每个文件分配唯一 ASCII 文件名。
只在临时副本里将 Include 文件名卡改为该别名、已验证的搜索目录卡改为 `.`；数值卡、源文件和正式
保存树不改。包含续行的文件名沿用共享 `file_names` 解析，未改行字节和 CR/LF/CRLF 保留。
这样 4.10 也从自有 job cwd 读到正确依赖，不需要在用户目录运行。

读取前检查全部文件/候选/目录的允许范围、网络名称和引用预算；有歧义的解析拒绝。
每份副本与源字节均做全量 SHA256，重开后复核源目录清单及副本身份。成功只清理仍匹配创建身份和
哈希的自产输入文件，不递归删除、不删除未知文件；变化/失败副本保留。复制前保留 64 MiB 磁盘余量。

共享模型解析还修复两条基础问题：按源编码解释 UTF-8/GBK 文件名；保留 UTF-8 BOM 字节并识别首行
关键字，使 BOM 不能隐藏 Include/网络引用。UTF-16 原生准入及不支持的格式限制保留。
