# ADR 0001：会话传输方式

状态：E1–E4、本机锁屏与 UU 远程断开实验已记录；用户确认 UU 在全部测试区间保持断开并于结束后重连。UU 条件与传输决策已确认；完整远程矩阵尚有 13 格未测，M0-4 保持 partial，等待用户决定补测或转入 I04。

## 问题与选项

当前 cfile + 应用内 bridge + complete.json 已能关联请求，触发仍依赖 Win32 命令框。候选方案为 E1 后台线程直接调用、E2 主线程定时/空闲回调、E3 主线程轮询、E4 socket/队列 + 主线程执行。保留当前 Win32 作为对照与候选后备。

## 实验证据

脚本与操作步骤见 [experiments](../../tools/experiments/README.md)，逐格证据摘要见 [实验数据](0001-experiment-evidence.json)。实验为本项目原创 8 节点 keyword 和 3 状态壳结果，实际构建为 Windows x64 LS-PrePost 4.13.4（17Dec2025）；4.10 按本机安装执行批处理子集。

| 实验 | 观察 | 判定 |
|---|---|---|
| E1 后台线程直接调用 | 200 秒内未完成首条命令，无完成回执；主窗口可刷新 | 此候选未通过，不能据此猜测具体 GIL/原生线程根因 |
| E2 回调发现 | DataCenter/LsPrePost 的实际 dir() 无 timer/idle/callback/event/pump 候选；已查本地 Scripting API 文本，未发现对应入口 | 没有成功注册回调；不杜撰 API |
| E3 主线程文件轮询 | 1000 条命令逐条选区读回正确，PNG 解码通过；运行中对该进程窗口的 activate_window 超时 | 数值通过，GUI 不冻结条件未通过 |
| E4 socket/队列 | 1000 条命令读回与 PNG 通过；将步间隔延长至 0.1 秒后，处理中窗口激活仍超时 | 按任务书“同 E1”的 1000 条、无崩溃/死锁、结果正确判据通过；GUI 响应限制单独保留 |
| E5 锁屏 | WTS 会话锁定标志确认锁屏；两版本 c= -nographics 的四种普通脚本执行与 PNG 通过；4.13 会话也收到有效回执 | 仅限本次语料和精确启动方式；远程断开仍未测 |

锁屏组复用一个预先创建的会话，未锁屏组逐 lane 新建会话，因此后续 MP4 差异不能单独归因于锁屏。首个新会话的 command lane 可直接对照。每格保留启动参数、状态、回执、产物校验与原生日志；摘要包含原始记录 SHA256，原始日志/路径只留本地。

锁屏初试 v6 曾把输入桌面名 Default 误当成已解锁，相关状态中断记录作废，不纳入本表。修正后使用 WTSINFOEX_LEVEL1_W.SessionFlags 重跑；它与输入桌面可访问性是不同条件，见 [Microsoft 定义](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/ns-wtsapi32-wtsinfoex_level1_w)。

## 决策规则

按任务书使用各实验自己的判据：E1 连续 1000 条命令无崩溃、无死锁且结果正确；E2 能注册回调；E3 GUI 不冻结且渲染正常；E4 同 E1；E5 在指定环境核对产物。GUI 响应是 E3 的明确门槛，不能额外加到 E1/E4 上再把其通过改为失败。

E1/E3/E4 任一通过其判据，则选择 bridge 自行取请求并保留 Win32 后备；全部失败才保留 Win32 为会话主触发。

BatchEngine 的主路径决定保持；各通道在 runc=、c= -nographics、session 与桌面/锁屏/RDP 状态分别留证。4.13 全矩阵，4.10 两个批处理列。传输选择不会把会话请求偷偷变成新后台实例。

## 后果

**决定：M1 采用 E4“后台 socket 收发 + 主线程队列执行”作为非交互常驻 SessionEngine 的实现路线，Win32 保留为观察模式与兼容后备。** E4 已满足任务书的有限稳定性判据；主线程循环阻塞界面的观察结果仍是该路线的已知限制。M0 只记录决定，不替换运行时。M1 必须把请求关联、超时、退出、执行后的校验和版本边界接入统一 Engine/JobResult；不能把 1000 条选择命令的证据推广成全部领域操作已验证。

用户明确使用 UU 远程，本次 E5 远程条件据此改为 UU 断开，不再要求提供 Windows RDP。RDP 保留为未经验证的另一环境。2026-10-05 18:12:44–18:17:02（UTC+08:00）执行了 UU 时间窗探针：4.13/4.10 的 c= -nographics，以及 4.13 观察会话，共 12 组普通通道执行和 PNG 通过；4 组观察会话 MP4 通过，8 组批处理 MP4 保留已知 640×476 尺寸失败。另在 I01 分支通过新引擎六项原生回归。

Windows 全程记录为 Console、unlocked；该状态不能证明 UU 是否连接，因此断开条件使用用户的起止时间确认；用户已明确确认整个 18:12:44–18:17:02 区间一直断开、现在已重连。去路径证据附在实验数据 uu_disconnect 中；原始记录、UU 探针脚本和产物仅保留本地，复现入口为 tools/experiments/run_remote_probe.py。远程探针覆盖已选定的 c= -nographics 默认批处理与观察会话；runc=、原生宏的 UU 断开格未执行，既有本机证据与这些未测格分别保留。M0 任务书要求每格覆盖远程断开状态；这些 13 格缺口不能靠已有本机结果替代。是否把剩余格转入 I04，须由用户明确决定。

## 附加原生复现

在同一原创 keyword 上，连续 genselect add 两个不同节点后实际读回成员并集；顶层 inctreeinfo2file 被原生拒绝且没有产物，但进程退出码仍为 0。两条原先只有评审观察的记录现有本轮证据，见 KI-045/KI-046；报告、源码和原生日志 SHA256 附在实验数据中。

原生宏追加复核：`m=` 装载完整 `.mac`；实际菜单为 Misc. → Launch Macro Interface。窗口出现不代表输入模型已加载，增加独立节点计数回执后才允许 Exec。菜单/Exec 同步消息超时后不重发，仅通过真实面板和新回执核对实际结果。未锁屏新会话下三项通过，MP4 为 640×480、5 fps、3 帧；早期 winmacro 错误候选和输入竞态失败仍留本地。

批处理电影尺寸追加对照：在 4.13/4.10 两版本各用 `w=1024x768`、`w=640x480` 运行同一 `c= -nographics` 程序，四次都得到 640×476、5 fps、3 帧，完整解码通过。窗口尺寸参数未修复请求高度偏差；不通过改写期望尺寸或转码来算作 640×480 验收成功。去路径记录与源程序哈希附在实验数据中。
