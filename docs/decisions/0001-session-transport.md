# ADR 0001：会话传输方式

状态：待 E1–E5 实验；M0-4 尚未完成。

## 问题与选项

当前 cfile + 应用内 bridge + complete.json 已能关联请求，触发仍依赖 Win32 命令框。候选方案为 E1 后台线程直接调用、E2 主线程定时/空闲回调、E3 主线程轮询、E4 socket/队列 + 主线程执行。保留当前 Win32 作为对照与候选后备。

## 实验证据

脚本与操作步骤见 [experiments](../../tools/experiments/README.md)。离线检查不证明原生可用。尚未获得本次 E1–E5、锁屏或 RDP 断开实测记录；不得以既有批处理或可见 GUI 通过代替。

## 决策规则

E1/E3/E4 任一满足其稳定性、正确性及 GUI 响应判据后，才选择自行轮询并保留 Win32 后备；全部失败则保留 Win32，SessionEngine 继续次要。E1/E4 要求连续 1000 条命令；E3 要求界面不冻结且渲染正常；E2 必须成功注册回调，只有 dir() 候选名称不算通过。

BatchEngine 的主路径决定保持；各通道在 runc=、c= -nographics、session 与桌面/锁屏/RDP 状态分别留证。4.13 全矩阵，4.10 两个批处理列。传输选择不会把会话请求偷偷变成新后台实例。

## 后果

未完成实验前不重构运行时，也不宣称锁屏可用。M1 的 SessionEngine 实现与版本能力表须引用最终实验数据；如果 RDP 环境不可用，由用户决定如何处理该验收项。
