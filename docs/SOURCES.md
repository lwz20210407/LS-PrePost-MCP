# 来源吸收与验收追踪

可查询的机器记录位于 `src/ls_prepost_mcp/data/`：

- `sources.json`：公开仓库、官方资料、标准案例与自定义工作流的来源、真实功能、许可和接入状态。
- `commands.tsv`：Hydrowelder 命令目录，保留上游许可；用于 `search_commands`，不用于绕过执行检查。
- `workflows.json`：官方球撞板、Element Editing、ElGen、Block Mesher、修复和中面教程的逐步参数与验收建议。
- `capabilities.json`：实施与验证状态，不把文档存在等同于工具可执行。

## 吸收规则

| 来源 | 当前接入方式 | 下一步 |
|---|---|---|
| Malps-del MCP | 任务/模板/验证分层经验，独立实现核心 | 按能力比较，补充已验证配方 |
| Hydrowelder | 可检索的完整命令表、Apache-2.0归属 | 版本化参数定义与配方验证 |
| 官方 SCL/Python | 应用内查询、网格、绘图与SCL探针 | 应力/积分点、选择、结果回传 |
| 官方 Tutorial | 逐步骤验收清单 | 将任务依次提升为可执行配方 |
| 本地标准案例 | API/输入输出/缺陷索引，回归测试 | 参数化各案例、真机数值对照 |
| 本地骨料/失效等 | 真实能力分类、硬编码及错误记录 | 创建模型选择、分区、失效工具 |
| LASSO | 已接可选数据后端 | 更多实体量、能量与大文件选择读取 |
| PyDYNA、K-agent | Deck与质量门槛参考 | 后续建模和验证后端 |
| PyCompact/SPHgen等 | 专项生成流程参考 | 许可核实、重构、样例验收 |

## 已转换为回归要求的问题

- X/Y/Z必须来自各自分量，不能沿用三份相同脚本。
- 合位移与三个分量计算保持一致，保存与绘图应使用同一结果。
- user ID不能由数组下标代替；未知实体必须失败。
- 公开状态从1开始，读取器内部索引必须显式转换。
- 旧输出文件不能证明新任务成功；零退出码仍需有效响应和产物。
- 三个正应力的欧氏范数不是通用von Mises；未来应力工具需要六分量基准。
- 随机骨料分区、真实球体网格、函数绘图与结果提取分别标注。

索引状态 `reference_indexed` / `recipe_candidate` 表示资料已纳入设计输入；只有代码实现及实机证据齐备的功能才提高验证等级。所有来源有接入记录，不意味着所有功能在首版一次实现。
